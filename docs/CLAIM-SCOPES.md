# 文风 · 厂商认领权限矩阵

> 2026-09-23 定调。认领页、厂商页 CTA、以后厂商后台都以本文为准。许可与防钓鱼见 [LICENSE.md](LICENSE.md)；双平台分工见 [PLATFORMS.md](PLATFORMS.md)。

## 1. 原则

- **认领 ≠ 许可核对**。`foundries[].claimed` 只说明谁在维护这一页；每款字的档位与「已核对」仍走 `licenseEvidence`，厂商后台不得改。
- **认领主体 = 该页对应的字典条目**。某款字的归属页只由 `ownerId` 认领；制作方（`makerId`）只认领自己的字库页，**无**单独「制作方协作」通道。受托列表说明由本站维护。
- **范围由 `kind` + `openSource` 推导**，暂不增加 `claimScope` 字段。`unlisted` 不可认领，须先归并字典。
- 本阶段前端只做分型文案与表单；真审核 API / 字段级 ACL 另接。

## 2. 权限矩阵

| kind | 页上称呼 | 可认领？ | 通过后可改 | 明确禁止 |
|---|---|---|---|---|
| `brand` | 品牌方 | 是 | 本页标志、介绍、官网 | 改制作方页；改任何字的许可或 `verified` |
| `foundry` | 字库 | 是 | 同上；自家有归属字的展示优先序（后台再做） | 把受托款说成自有版权；改品牌方许可 |
| `author`（非开源） | 作者 | 是 | 简介、头像、外链 | 把平台转载款认成「我的字」；改许可 |
| `author` + `openSource` | 开源作者 | 是 | 同上，可挂仓库 | 同上；派生 / 源文件 / 缺字走 [wenfeng.org](https://wenfeng.org) |
| `project` | 开源项目 | 是（材料更严） | 项目说明、仓库、许可原文链（页资料） | 个人无证明认领整仓；改库内字的核对状态 |
| `platform` | 素材平台 | 是 | 介绍、官网、标志 | **许可档位**、「已核对」、`sourceKind`；不得自证「可商用」 |
| （无 kind / `unlisted`） | 未核对 | **否** | — | 须先归并 `foundries.json` 再提交 |

## 3. 审核材料（按类型）

共用：厂商法定名或已收录名、官网、官网域名邮箱。

| kind | 额外材料 |
|---|---|
| `brand` / `foundry` / `author` | 授权原文链接（对照库内字体；**不**等于通过后可改许可） |
| `project` | **必填**仓库或组织证明链接（维护者 / 组织页） |
| `platform` | 平台关于页或更正说明（可选）；不把「授权原文」当成许可核对方 |

## 4. 出现位置

- **内部**：矩阵与材料规则写在本文；运行时 `WFChrome.claimProfile(foundry)` 供审核与表单字段推导（如开源项目要仓库证明）。通过后的页在控制台「我的页」，见 [CONSOLE.md](CONSOLE.md)。
- **公开 UI 用通用文案**，不展开可改/禁止清单：
  - 认领页：通过后可维护标志、介绍与官网；许可仍以每款字体出处为准。
  - 厂商单页：`这是你的品牌？认领此页。通过后可改标志与介绍。`
  - 厂商索引底部：合作入驻 + 准备法定名称 / 官网邮箱 / 授权原文。
- 禁止在公开页按 kind 写「素材平台不能改许可」等内部口径；细节只留本文与后台。

## 5. 不要做的

- 认领通过后让厂商点亮「免费商用 / 已核对」。
- 给制作方开通改品牌方页或改许可的通道。
- 素材平台自证许可或改 `sourceKind`。
- `unlisted` 直接认领进正式目录。
- 本站另发「文风厂商许可证」冒充权利人授权。
