# 文风字体 · AI 原生工作要求

> 本仓默认由 AI 智能体（Cursor / Claude Code / Codex 等）与人协作开发。本文规定智能体在本仓工作的边界、流程与交付标准；同时给出产品层"AI 原生"能力的需求基线。

## 1. 开工前必读（顺序）

1. `docs/ai-context/project-structure.md` — 技术栈与文件树
2. `docs/DESIGN-SYSTEM.md` — 视觉规则与组件目录
3. `docs/FRONTEND-STANDARDS.md` — 代码规范与数据契约
4. `docs/PLATFORMS.md` — 双平台分工（Windfonts 分发 / wenfeng.org 造字与授权）；动厂商、开源作者、缺字、造字时必读
5. `docs/LICENSE.md` — 授权依据、来源分档、防钓鱼；动授权区 / 厂商认证时必读
6. 与任务相关的页面 HTML、其 `js/pages/*.js`，以及被引用的 `wf-*.js`
7. `styleguide.html`（可在浏览器打开）核对组件长相

不读文件就动手、凭记忆猜类名或令牌名，是本仓最常见的返工来源。

## 2. 不可逾越的边界

| 禁止 | 替代 |
|---|---|
| 新增颜色值 / 彩色点缀 / 红色 | 用现有令牌；状态用文字 + `status-dot` |
| 引入框架、构建工具、npm 运行时依赖 | 原生 HTML/CSS/JS |
| 手写 `<link>` 到 CDN、拼 CDN 地址字符串 | `WFProto.cssUrl` / `ensureFontCss` / `WFEmbed` |
| 在页面里写厂商名、英文名、官网 | `data/foundries.json` + `WFChrome.brand*` |
| 用占位文案、假数据、`TODO` UI | 补全 `mock-app.json` 的真实结构化数据 |
| 混入其他图标集、内联随手画的 SVG | MingCute（motucloud）→ `assets/icons.svg` |
| 修改 `data/fonts.json` 手工字段 | 改 `scripts/export-fonts.mjs` 或 `foundries.json` |
| `git commit` / `git push` / 删分支 | 完成后报告，由用户决定提交 |
| 启动长期运行的服务并留着 | 告知用户如何本地预览（任意静态服务器指到仓根） |
| 创建 README / 文档以外的 `.md`（未被要求） | 更新 `docs/` 既有文件 |

## 3. 标准工作流

```
理解 → 读相关文件 → 列 todo → 最小改动 → node --check → 截图 + 控制台清零 → 更新 docs/styleguide → 汇报
```

- **理解**：把用户一句话拆成可验证的条目；有歧义先按最合理解释做完不依赖歧义的部分，再在汇报里写清假设。
- **最小改动**：改现有文件优先；一个页面一个 `js/pages/*.js`；共享逻辑进 `wf-*.js` 并挂到既有命名空间。
- **验证**：headless Chrome 截图（1440 / 390）、`--enable-logging=stderr` 抓错；控制台页面加 `?demo=1` 自动登录；深色模式加 `?theme=dark`。截图放 `/tmp`，不进仓。
- **汇报**：列出改了哪些文件、为什么、怎么验证的、哪些是拟定 / 待确认（如厂商中文名 `provisional`）。不夸大，不写没验证过的结论。

## 4. 交付定义（DoD）

一项 UI 任务视为完成，需同时满足：
- 亮 / 暗两种主题下截图无溢出、无重叠、无颜色泄漏；
- 涉及页面控制台无 `Uncaught`、无 404（favicon 除外）；
- 所有可点击项有反馈（toast / 状态变化 / 跳转）；空态、加载态、错误态齐备；
- 文案符合 `DESIGN-SYSTEM.md §6`（中文、全角标点、动词短语）；
- 新增组件 / 令牌 / 数据字段已写入对应文档与 `styleguide.html`；
- 没有留下临时文件、调试 `console.log`、注释掉的代码。

## 5. 多智能体协作

- **决策分级**：D0 日常实现（直接做）· D1 局部设计（可请一个外部模型评审）· D2 改令牌 / 数据契约 / 信息架构（必须交叉验证：至少一个外部模型 review 后再改）· D3 换设计方向（用户拍板 + 对比页试点，如 `design-options.html` 的 A/B/C/D 做法）。
- **并行拆分**：按页面拆（一个智能体一个 `pages/*.js` + HTML），共享层（`wf-*.js`、`tokens.css`、`components.css`）同一时间只允许一个智能体改，改完先合再派发下一批。
- **上下文注入**：派发子任务时必须附上本文件、`DESIGN-SYSTEM.md`、目标页面路径与验收标准；子智能体不得自行扩大范围。
- **评审**：D2 以上变更用 Bugbot / Codex 做一次代码评审，关注：转义遗漏、令牌绕过、数据结构与文档不一致、事件重复绑定。

## 6. 产品层 AI 原生能力（需求基线）

以下是后续版本要实现的 AI 能力；前端已为其预留入口位置，接口契约见 [HANDOFF.md](HANDOFF.md)。

| 能力 | 入口 | 要求 |
|---|---|---|
| 智能选字 | 首页 / 字体库控制条的搜索框 | 支持自然语言（"适合茶叶品牌的手写体"），返回字体列表 + 一句话理由；结果可加入选字袋 |
| 样张文案生成 | 控制条预设旁 | 根据字体气质生成 1–3 条示例文案；用户可编辑；不含敏感内容 |
| 字体配对 | 详情页侧栏 | 推荐 2–3 款标题 / 正文搭配，给出字重建议与嵌入代码 |
| 子集化建议 | 控制台子集化工作台 | 粘贴页面 URL 或文本，自动抽取字符集与频次，推荐"按文字 / 3500 / 7000"并估算体积差 |
| 用量洞察 | 控制台用量 / 字体钻取页 | 自动指出低使用字重、异常 403 来源、配额预警，附一键动作（移除字重 / 加白名单） |
| 文档问答 | 文档页目录搜索框 | 基于 `docs.html` 内容与 CDN 规则回答接入问题，回答里给出可复制代码 |
| 厂商资料补全 | 厂商认领流程 | 从官网抓取中文名 / 英文名 / 简称 / 简介草稿，人审后落到 `foundries.json` |

**统一要求**：AI 输出必须可编辑、可撤销、来源可见（标注"AI 建议"），失败时静默降级为非 AI 路径；不把用户上传的字体文件或页面文本用于训练；所有 AI 调用走后端代理并带请求关联 ID，前端不持有模型密钥。

## 7. 后续开发（人 + AI）的工作要求

- 新页面：复制同类页面 HTML 骨架 → 新建 `js/pages/{name}.js` → 加入导航常量（`WFChrome.NAV` / `WFApp.NAV`）→ 补 `styleguide` 与文档。
- 新组件：先在 `styleguide.html` 画出样张并获认可，再进 `components.css` 与组件目录表。
- 新数据字段：先改契约文档，再改 mock / 导出脚本，最后改渲染。
- 接后端：只替换 `wf-proto.js` `loadCatalog` 与 `wf-app.js` `load/save` 的实现，保持返回结构；页面零改动是验收标准。
- 每次迭代结束更新 `CHANGELOG-*.md` 一段（做了什么、为什么），供下一个智能体接手。
