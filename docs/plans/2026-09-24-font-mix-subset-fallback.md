# 多字体调用 · 自选字 · 谱系缺字补全（讨论稿）

对照日期：2026-09-24。只谈产品与接口边界，**未开工**。

## 0. 共识

| 点 | 结论 |
|---|---|
| 公开 `GET /api/css?text=任意文案` 即时切字 | **不做**（缓存爆炸、滥用、边缘算力） |
| 多字体同页使用 | **要做透**，分「显示栈」与「一次拉多款」 |
| 用户自选字集 | **要做**，走登录项目 / 鉴权编译，不走公开查询参数 |
| 谱系缺字补全 | **值得做**，优先 CSS 级自动回退；强拼字另议 |
| 短码 `family=` 与 `charset`/`purpose` | 参数化另批，须点头；见 FAMILY-VARIANTS |

## 1. 多字体混合调用

### 1.1 页面层（零 API 改动）

```css
font-family: "wenfeng-albbpht", "wenfeng-ibmps", sans-serif;
```

浏览器按字形缺失自动回退。这是最便宜的「混合显示」。  
局限：整段共用一个栈；无法指定「这个字必须用 B」。

### 1.2 CDN 一次拉多款（文档已写）

```
/api/css?family=wenfeng-a|wenfeng-b&weight=regular&subset=full
```

返回多段 `@font-face`，CSS 里再分角色（标题 A / 正文 B）。  
前台待办（未做）：嵌入生成器 / 选字袋支持勾选多款并生成 `|` 地址。

### 1.3 不做的默认能力

「同一段文字按码点自动拼多款字库」作为**公开默认**产品：成本高、观感难控（字重/字面不一致），不进 v1。

## 2. 自选字（鉴权路径）

### 2.1 现有档位

| 层 | 能力 | 谁用 |
|---|---|---|
| 公开预设 | `subset=full \| zh \| zh-common \| en` | 任何人 |
| 控制台子集化 | 按文案 / 常用字 / 编码范围 → 项目字体 | 登录用户 |
| 文档草图 | `POST /v1/subset` + `text=` | 计划中的鉴权 API |

### 2.2 推荐形态（v1）

1. 用户在控制台选定字体 + 字表（粘贴文案或范围）。  
2. 服务端编译子集包，写入项目 / 得到**稳定 URL**（或带签名的短期 URL）。  
3. 嵌入仍用 CDN 域名；鉴权在「编译」与「域名白名单」，不在每次公开 GET 上现切。

可选进阶：`chars=` / `text=` 仅出现在 **Bearer / 项目密钥** 的 API，结果进 CDN 缓存键（含用户/项目维度），绝不挂匿名 `/api/css`。

### 2.3 明确不做

- 匿名 `GET /api/css?...&text=...`  
- 把动态默认主机改成 `app.windfonts.com` 绕过 CDN（硬约束）

## 3. 谱系缺字补全（新议题）

动机：派生款常比源头字少；同谱系（思源系、LXGW 系等）视觉接近，用上游补洞比系统默认宋体/黑体更顺眼。

### 3.1 方案 A · CSS 回退栈（推荐先做）

对「当前款 + 谱系上游（或同 group 指定补全款）」生成：

```css
font-family: "wenfeng-derived", "wenfeng-upstream", sans-serif;
```

并一次或两次拉 CSS（或 `family=derived|upstream`）。  

**优点：** 浏览器原生按缺字回退；与现有 lineage 数据（`upstreamName` / `group`）可对齐；无新切字管线。  
**缺点：** 全段指标跟主字体；补全字可能略「跳」；须两边许可都允许此用法（开源栈通常 OK，仍要写清责任）。

产品形态候选：

- 详情「使用」区：勾选「缺字用上游补全」→ 生成栈 + 多 family 链接  
- 控制台项目：为某字体绑定 `fallbackFamily`  
- 不默认替用户打开（避免体积与意外换字）

### 3.2 方案 B · `unicode-range` 分区

主字体声明自己的 range；补全字体只挂「主字体没有的码点」。观感更可控，但要：

- 可靠的「主字体 cmap / 覆盖表」（现网字符表已有 unicode-range 核对能力）  
- 服务端或构建时生成组合 CSS  

适合作为 A 的加强版，不是第一步。

### 3.3 方案 C · 服务端拼字 / 运行时换 span

按字拆 DOM 或合成一张虚拟字库。体验可做到「无缝」，工程与合规成本最高，**暂不排期**。

### 3.4 约束与风险

| 项 | 说明 |
|---|---|
| 许可 | 补全源与主字体均须允许网页嵌入；RFN / 署名按各许可原文 |
| 字重对齐 | 尽量同 weight token；对不齐时降级或提示 |
| 简繁 / 地区版 | 台湾系等已有「不做简体千字文盘点」等特例，补全策略要跟 skip 规则一致 |
| 体积 | 多拉一款完整或 zh 包；须在 UI 标明 |
| 谱系数据 | 依赖 `lineage.upstreamName` / `group`；断链或库外源头只能提示，不能瞎补 |

### 3.5 建议落地顺序（缺字补全）

1. **讨论定稿**：默认关、用户显式开；补全源 = 谱系上游（可覆盖为同 group 指定款）。  
2. **前台**：详情嵌入生成器输出双 family 栈（A）。  
3. **验证**：挑 2～3 条派生链（思源派生、LXGW 派生）看观感与体积。  
4. 若不够：再评估 B（unicode-range 组合 CSS）。

### 3.6 简繁互为补全（2026-09-24 讨论）

动机：简体款缺繁码点、或繁体款缺简码点时，能否用「另一侧字形」顶上？

**关键事实：浏览器按 Unicode 码点找字，不会自动把「国」当成「國」。**  
CSS `font-family` 回退只在**同一码点**于上一款缺失时换下一款；它**不会**做 OpenCC 式简繁映射。

| 做法 | 能否补「另一侧码点」 | API / 产品形态 | 态度 |
|---|---|---|---|
| **A. 简繁产品兄弟入栈** | 能（文本本身已是繁或简码点） | 与谱系补全同构：`family=主\|兄弟`；可选查询键 **`localeFallback=sc\|tc\|auto`**（解析成第二短码，不新发明切字参数） | **可做**；依赖 `font-products` / 目录里的 SC·TC 配对 |
| **B. 服务端改写页面文案**（s2t/t2s） | 能，但改的是字不是字体 | 不属于 `/api/css`；属站点或 CMS | **不做进 CDN API** |
| **C. 合成虚拟字库**（缺繁用简轮廓挂到繁码点） | 能「看起来有字」 | 重管线；RFN / 观感 / 错字风险高 | **不做**（近中期） |
| **D. 覆盖 API 提示** | 决策辅助 | `GET …/coverage?text=`（鉴权）返回缺字 + 可选「同字体是否有简/繁对应码点」 | **可后置**；给工具链，不挂匿名 css |

与谱系补全的分工：

- **谱系上游**：同款视觉血统、字数更多 → 补「本款没有的字」。  
- **简繁兄弟**：同产品另一地区规格 → 补「另一套码点」；文本必须已是那套码点（用户写繁、栈里有繁款）。

公开 `/api/css` **不要**加 `convert=` / `opencc=` / `han=trad`。  
若要选项，只加「第二 family 从哪来」的开关（`localeFallback` 或前端勾选），底层仍是已有的 `family=a|b` + 同 `subset`。

**一句话：** 简繁补全能做，但是「再拉一款简/繁规格做 CSS 回退」，不是「API 把缺的繁画成简」。

### 3.7 系统端预做 · 用户只调参数（拍板向）

目标：配对、解析、出栈都由 **vault / 目录**做完；调用方不必知道兄弟短码，只改选项。

**服务端预先准备（构建期 / 同步期）：**

| 预计算 | 内容 |
|---|---|
| 简繁配对表 | 从 `font-products` / 目录标出 `scFamily` ↔ `tcFamily`（及日韩等地区变体若有） |
| 可开补全标记 | 两边都允许网页嵌入、字重可对齐、均有对应 `subset` 包，才 `localeFallbackAllowed=true` |
| （可选）组合 CSS 缓存键 | `family + weight + subset + localeFallback` → 已展开的多 `@font-face` 响应 |

**运行时用户只碰参数（建议形态）：**

```
GET /api/css?family=wenfeng-xxxsc&weight=regular&subset=zh&localeFallback=auto
```

| `localeFallback` | 服务端行为 |
|---|---|
| 缺省 / `off` | 只出主 `family`（现状） |
| `auto` | 若配对表有兄弟且允许 → 展开为 `主\|兄弟`，同 weight/subset |
| `sc` / `tc` | 强制指定方向的兄弟；无配对或未允许 → 忽略或 4xx（实现时二选一，建议：无配对则静默仅主款 + 响应头提示） |

响应仍是一段 CSS：主款 + 兄弟款的 `@font-face`（字形 URL 继续指向 CDN 分片）。  
页面 `font-family` 文档写清须带两名，或 CSS 里用 `font-family: "主", "兄弟", …` 由生成器/文档约定——**嵌入生成器勾选「简繁补全」只改这一参数**，不改短码心智。

**系统做不到、也不预做的：**

- 把页面里的「国」改成「國」或反过来（改文案属站点，不属字体 CDN）  
- 在同一码点上挂另一侧轮廓冒充已收录（虚拟字库）  
- 无配对数据时凭空猜一款繁/简

**与谱系补全参数并列（勿挤进 subset）：**

| 参数 | 含义 |
|---|---|
| `subset` | 字量表（en / zh-common / zh / full） |
| `localeFallback` | 是否附带简繁兄弟款 |
| （将来）`lineageFallback` | 是否附带谱系上游；或继续只用前端/`family=\|`，不新开键也可 |

两者都是「第二 family 从哪来」，**缓存键必须带上**，默认关。

**落地顺序：** 先配对表进 vault 同步 → `/api/css` 认 `localeFallback` → 前台嵌入勾选只写该参数。N1 回源打通后，用户复制的 cn 链接才能带上这个选项生效。

### 3.8 延伸想法取舍（2026-09-24）

| # | 想法 | 结论 |
|---|---|---|
| 1 | 场景配方 `preset=brand\|article\|ui` | **先不弄** |
| 2 | 补全时**字重对齐**（同 weight token；对不齐降级/拒绝 + 提示） | **可以**（跟谱系 / 简繁补全一起做） |
| 3 | 覆盖差 API（主 vs 兄弟/上游缺哪些码点） | **可以**（工具向，鉴权或轻限流；不挂匿名 css） |
| 4 | 两段加载（先 en 再 zh）当通用体验优化 | **不做这套叙事**。`en` / `zh*` **有意拆分**：不少中文字体不做拉丁或拉丁很差，文风用独立档让用户显式选，不是单纯为了体积分片 |
| 5 | 嵌入预算模式（预估 KB / 开补全后对比） | **可以后续**（依赖包体清单） |
| 6 | 复杂组合进项目 `/p/{slug}` 一次烘焙 | **可以考虑**（公开 css 保持瘦参数） |
| 7 | 匿名 `text=`、改文案、虚拟挂轮廓、泛 AI 聊天 | **先不弄**（维持 §0 / §3.6 不做项） |

对第 4 点的产品含义：四档里的 `en` 是「拉丁质量可用时的显式选择」，不是默认首屏垫片；生成器/文档不要暗示「先挂 en 再补中文」为推荐路径，除非用户本页确实只要拉丁或主字体拉丁不可用而另挂西文款。

## 7. CDN / CSS 效率（讨论提纲，未开工）

目标：在不改「CDN 域名 + `/api/css`」对外口径的前提下，少传字节、少建连、少重复 `@font-face`。

### 7.1 已有杠杆

| 手段 | 作用 |
|---|---|
| 分包 + `unicode-range` | 浏览器只拉用到的片（cn-font-split） |
| 预设 `subset` | `zh` / `zh-common` / `en` 比 `full` 小 |
| 项目子集化 | 按真实文案再瘦 |
| `preconnect` + 预加载 CSS（非字体文件） | 文档已建议；勿 preload 具体 woff2 片 |

### 7.2 可继续谈的方向

1. **组合请求**：`family=a|b` 时边缘合并成一份 CSS，共享缓存策略与压缩，避免两次 RTT。  
2. **谱系补全与体积**：默认关；开启时优先 `subset=zh` 拉上游，避免双份 `full`。  
3. **字重收敛**：嵌入生成器默认只勾用到的 weight；多 weight 用可变字体（若有）或明确「一页一主重」。  
4. **缓存键**：`family+weight+subset(+projectId)`；鉴权编译结果长缓存，HTML 用短链或 immutable 版本号。  
5. **CSS 瘦身**：去 `local()`、统一 `wenfeng-*` family（现网已做）；合并重复 `unicode-range` 规则；Brotli/压缩在边缘。  
6. **HTTP**：HTTP/2～3 多路复用；字体 `font-display: swap`（或可选 `optional` 首屏）；CORS / COEP 与跨域字体一致。  
7. **边缘**：`/api/css` 回源 vault（infra），公开站不因 OSS 404 改口径。  
8. **观测**：按 family/subset 看命中率与字节，驱动默认 subset 与补全策略。

细节与取舍见下轮讨论；**本节不授权改接口或上线行为**。本节方向（少拉 / 合并拉 / 缓存键 / CSS 瘦身 / 边缘回源 / 观测）**已记档**，实施另批。

## 8. 无损压缩：CSS 与字形/字符（讨论）

问的是：在**不丢码点、不改轮廓语义**的前提下，CSS 与字体字节还能怎么压。  
（子集化会丢掉未选用的字——对保留部分无损，对整库是「减负」不是压缩算法。）

### 8.1 传输层（CSS 文本、JSON、HTML）

| 方式 | 性质 | 说明 |
|---|---|---|
| **Brotli** | 无损 | 现网 CDN 首选；对重复多的 CSS（大量相似 `@font-face` / `unicode-range`）收益通常优于 gzip |
| **gzip / deflate** | 无损 | 兜底；可用 Zopfli 做离线更优 gzip（编慢、解压仍兼容） |
| **压缩字典（Brotli/Zstd shared dict）** | 无损 | 多份结构近似的 `/api/css` 可共享字典，再压一截；要边缘与客户端协商，工程量中等 |
| **minify** | 无损（语义） | 去空白/注释；收益有限，组合 CSS 仍值得做 |

字符本身作为 Unicode 文本：网页场景几乎不靠 SCSU/BOCU 等「Unicode 压缩」；有效路径仍是 **Brotli 整份 CSS**。

### 8.2 字体文件（轮廓数据）——主战场

| 方式 | 性质 | 说明 |
|---|---|---|
| **WOFF2** | 对 SFNT 的标准压缩（Brotli 系） | 公开 Web 字体的默认答案；比 WOFF1/ttf 明显更小 |
| **WOFF1** | zlib | 旧客户端兜底；新栈以 woff2 为主 |
| **CFF/CFF2 vs TrueType glyf** | 格式选择 | 同源不同封装，体积因字体而异；属制作管线，不是运行时算法 |
| **字体级 hinting / 冗余表剥离** | 制作时无损或近无损 | 去无用表、合并重复；须在打包流水线做，不进浏览器 |

没有一种「专压汉字」的魔法算法能在保留全 cmap+轮廓的前提下大幅替代 WOFF2；CJK 大，是因为**轮廓多**，不是 UTF-8 文本没压好。

### 8.3 「字符」相关、常被误认为压缩的手段

| 方式 | 是否算法压缩 | 说明 |
|---|---|---|
| **子集化 / 按文案切** | 减负 | 保留字形无损；未选字不提供 |
| **unicode-range 分包** | 按需加载 | 整包仍在 CDN；浏览器只拉用到片——效率核心 |
| **项目子集 + 长缓存** | 减负 + 缓存 | 与 §2、§7 同一条产品线 |
| **频谱/有损轮廓简化** | 有损 | 例如过度简化曲线；**公开正文一般不做** |

### 8.4 和当前栈的贴合建议（仍只讨论）

1. 确保公开与项目字体交付 **WOFF2 优先**（已是主流则核对覆盖率）。  
2. `/api/css` 与组合 CSS：**Brotli**；结构重复高时可评估 **共享字典**。  
3. 体积大头继续靠 **range 分包 + 合适 subset + 项目子集**，不是再找一种「压汉字」的编解码。  
4. 谱系补全开启时：两款都走 woff2 + 同档 subset，避免「压缩很好但仍拉了两份 full」。

### 8.5 不纳入

- 公开接口上对用户文案做奇特二进制字符压缩  
- 用有损简化字形冒充「优化」而不明示

## 9. 现网核验（2026-09-24，普惠体 Regular 抽查）

样本：`wenfeng-albbpht` + `weight=regular`。

| 检查 | 结果 |
|---|---|
| `cn.windfonts.com/api/css?...` | **404**（OSS `NoSuchKey`）——边缘未回源，与 HANDOFF 一致 |
| `app.windfonts.com/api/css?subset=full\|zh\|zh-common\|en` | **均 200** |
| `version=zh`（不带有效 subset） | 200，但注释仍是 `(full)`——**version 不换包**，须用 `subset`/`lang` |
| 字体格式 | CSS 内 **仅 `format("woff2")`**；抽查片为 WOFF2 / CFF |
| CSS 传输压缩 | 抽查为 **gzip**（`Vary: Accept-Encoding`）；本次未看到 `br` 响应 |
| 分包体量（CSS 原文近似） | `full` ~167KB / `zh` ~185KB / **`zh-common` ~7KB** / `en` ~2KB |
| 片数（`url(...woff2)` 约数） | full ~164 · zh ~186 · **zh-common ~4** · en ~1 |
| 预览包路径 | `cn.windfonts.com/fonts-packages/Albbpht/Regular/{full\|zh\|zh-common\|en}/result.css` 均 200 |

结论与此前判断一致：**效率最终落在「预计算哪一档子集包 + unicode-range 再切片」**；WOFF2 已是字形封装，再抠无损算法收益有限。公开 CDN 缺的是 `/api/css` 回源，不是缺一种新压缩格式。

## 10. 更多 API 参数是否可行？（品牌字 / 常用字等）

### 10.1 已经可行（现成参数）

公开（上游已认）预设档：

- `subset=full` — 完整拆包  
- `subset=zh` — 中文向  
- `subset=zh-common` — **常用字（抽查片数极少，适合品牌短文案）**  
- `subset=en` — 西文  

前台嵌入应继续双写 `subset` + `version`（同值），因边缘/旧读法不一致。  
**不要**指望只改 `version=` 换包。

### 10.2 「只调用品牌所需字」——可行，但是产品形态要选对

| 形态 | 可行性 | 说明 |
|---|---|---|
| A. 再用几个**命名预设**（如 `brand` / `logo` / `gb2312`） | **高** | 与 `zh-common` 同类：流水线预切 → 稳定 URL → CDN 长缓存。适合「行业常用字表」「品牌字库白皮书字表」 |
| B. 项目级自选字 → 稳定嵌入 URL | **高（推荐品牌客户）** | 控制台子集化；鉴权编译；不是公开 `text=` |
| C. 公开 `?text=` / `?chars=` 即时切 | **否**（已否决） | 缓存与滥用 |
| D. `charset` / `purpose` 映射到短码或预切包 | **中** | 见 FAMILY-VARIANTS；须改 vault + 点头，可把「品牌所需」做成 purpose 枚举而非自由文本 |

「品牌所需」若指**该品牌官网真实文案**：走 **B**。  
若指**一类站点共用的字表**（导航+页脚+按钮）：走 **A**（预切 `zh-common` 或新建命名档）。

### 10.3 建议怎么扩参数（仍未授权开工）

1. **先用好现有四档**：详情/文档默认引导 `zh` 或 `zh-common`，完整才 `full`。  
2. **加档只加「有字表、可预切、可缓存」的枚举**（例如 `zh-common` 已存在；可再评估 GB2312 / 品牌 UI 字表）。  
3. **品牌私有字表**不进公开枚举，进项目子集 URL。  
4. 修 **CDN `/api/css` 回源**，否则用户复制的 cn 链接全是 404，谈参数无意义。  
5. `family=a|b` + 统一 subset，服务谱系补全与多字体，仍用枚举 subset，不引入自由文本。

### 10.4 一句话

可以提供更多参数，但参数只能是**预计算分包的名字**（或项目 ID），不能是任意字符集；常用字 / 品牌短文案优先 `zh-common`（及同类新档），品牌长尾走子集化工作台。

## 11. 公开分包怎么分（建议档表）

原则：**按「页面会用到的字有多少」分档**，不按厂商、不按许可。每一档 = 固定字表 + 流水线预切 + `subset=` 枚举。自由文案不进公开档。

### 11.1 建议对外四档（与现网对齐，先用好）

| `subset` | 谁用 | 字表大致范围 | 体积预期 | 备注 |
|---|---|---|---|---|
| **`en`** | 纯西文 / 代码 / UI 英文 | 基本拉丁 + 常用标点数字 | 最小 | 现网已有 |
| **`zh-common`** | 品牌站、着陆页、导航+短文 | 常用汉字量级（约千字文～几千高频） | 小 | 现网已有；**品牌短文案默认首选** |
| **`zh`** | 中文正文站、博客、文档 | 通用中文覆盖（远大于常用字，仍可按 Unicode 再切片） | 中～大 | 现网已有；正文默认 |
| **`full`** | 生僻字、古籍、全量展示、不确定用途 | 字体 cmap 尽量全 | 最大 | 现网已有；不要当默认 |

前台嵌入生成器建议默认：`zh-common`（营销/品牌）或 `zh`（阅读站）；用户显式选「完整」才 `full`。

### 11.2 可选第五档（有字表再开，不先空挂参数）

| `subset` | 谁用 | 前提 |
|---|---|---|
| **`gb2312`**（名可再定） | 政企 / 国标口径正文 | 有稳定 GB2312（或 GBK 常用）字表，全库或核心库预切 |
| **`ui`** | 纯产品 UI（按钮、设置、报错） | 比 `zh-common` 更小的内部字表；与 `zh-common` 差不大就不必单开 |

**不开**公开档：`brand`（每品牌不同）、`logo`（过窄）、任意 `charset=` 自由串。

### 11.3 不放进公开 `subset` 的分层

| 层 | 放哪 | 例子 |
|---|---|---|
| 品牌私有用字 | 项目子集 URL / 鉴权编译 | 某官网全文、App 文案包 |
| 谱系补全 | 第二 `family` + **同一** `subset` | 主字体 `zh` + 上游 `zh`，不另发明 `subset=fallback` |
| 多字体角色 | `family=a\|b` + CSS 栈 | 标题/正文，不是新 subset 名 |
| 地区 / 简繁产品 | 短码 `family` 或 product 变体 | 见 FAMILY-VARIANTS；不是 `subset=tw` 糊弄 |

### 11.4 参数与缓存

- 公开只认枚举：`en | zh-common | zh | full`（+ 将来有字表的可选档）。  
- 双写 `subset` 与 `version`（同值）至边缘统一。  
- 缓存键：`family + weight + subset`；项目包另加 `project`/`hash`。  
- 新档上线标准：字表入库 → 核心字体预切完成 → 文档与嵌入 UI 可选 → 再写进 API。

### 11.5 决策一句话

**公开四档够用：西文 / 常用 / 中文 / 完整；品牌长尾用项目子集；谱系补全复用同一 subset，不新开档名。**

## 12. API 与参数（讨论定稿向）

三条对外路径，职责拆开，**不要挤进一个查询串**。

| 路径 | 谁用 | 干什么 |
|---|---|---|
| `GET {cdn}/api/css?...` | 任何人 | 拉**预计算**公开包 CSS（Google 风格） |
| `GET {cdn}/p/{slug}/index.css` | 项目嵌入 | 拉**已发布**项目包（多字体 + 设置已烘焙） |
| `POST {cdn}/v1/subset` | Bearer 密钥 | **编译**自定义子集；返回可缓存结果，不替代日常嵌入 |

主机一律 `cn|hk|en.windfonts.com`。禁止复制成 `app.windfonts.com` 当默认；禁止用 `fonts-packages/.../result.css` 顶替动态嵌入。

### 12.1 公开：`GET /api/css`

形态（前台 `WFProto.cssApiUrl` 已双写）：

```
https://cn.windfonts.com/api/css?family={family}&weight={weight}&subset={subset}&version={subset}
```

| 参数 | 必填 | 值 | 说明 |
|---|---|---|---|
| **`family`** | 是 | `wenfeng-{短码}`；多款用 `|` | 短码小写、不含字重；`\|` 一次返回多段 `@font-face` |
| **`weight`** | 是* | 字重名小写（`regular` / `heavy`…） | *缺省按 regular；**不用** `400` 数字当对外示例主形态 |
| **`subset`** | 是* | `en` \| `zh-common` \| `zh` \| `full` | *缺省建议文档写 `full` 或产品默认 `zh-common`；换包认这个 |
| **`version`** | 兼容 | **与 `subset` 同值** | 现网 vault **不认** `version` 换包；边缘未统一前继续双写 |

行为约定：

- 返回 CSS（`@font-face` + `unicode-range` 分片 URL），不是字体二进制。  
- 多 `family`：**同一** `weight` + **同一** `subset` 作用到整串；不同字重 / 不同档各发一条 `link`（或等项目 CSS）。  
- 缓存键：`family + weight + subset`（`|` 顺序规范化后再哈希）。  
- 别名：短码经 `family-aliases.json` 解析；公开 URL 仍输出规范 `wenfeng-*`。

**明确不加进公开 GET：**

| 参数 | 原因 |
|---|---|
| `text=` / `chars=` / `ranges=` | 缓存爆炸、滥用；走 `POST /v1/subset` 或项目 |
| `charset=` / `purpose=` | 与短码 / product 变体职责冲突；须另批点头 |
| `display=` | `font-display` 放项目烘焙或用户自写 CSS；公开默认 `swap` 即可 |
| `fallback=` / `lineage=` | 谱系补全用第二个 `family`（或项目设置），不新开查询键 |
| `format=` | 现网只出 WOFF2；无需用户选 |

### 12.2 项目：`GET /p/{slug}/index.css`

| 点 | 约定 |
|---|---|
| 参数 | **路径里只有 slug**；字重、subset、display、多字体已在发布时写死 |
| 鉴权 | Referer / 域名白名单（项目绑定）；公开 `/api/css` 不校验域名但限流 |
| 更新 | 发布新版本 → 同 URL 切内容；嵌入代码不改 |
| 与公开关系 | 品牌长尾、固定文案、多角色字体栈 → 优先项目；试水 / 文档示例 → `/api/css` |

可选（未拍板）：`/p/{slug}/v/{n}.css` 钉版本；默认 `index.css` = current。

### 12.3 鉴权编译：`POST /v1/subset`

文档草图已有；定位是**构建接口**，不是页面每次请求的嵌入 URL。

| 字段 | 必填 | 说明 |
|---|---|---|
| `family` | 是 | `wenfeng-{短码}` |
| `weight` | 是 | 字重名 |
| `text` **或** `preset` **或** `ranges` | 三选一 | 与控制台子集化三模式对齐 |
| Authorization | 是 | `Bearer $WINDFONTS_KEY` |

响应（建议形态，实现时对齐）：

- `201` + `{ "cssUrl": "https://cn…/…", "bytes": …, "expires"?: … }`  
- 或直接 `200` 返回 CSS，但**生产嵌入仍应落成稳定 URL**（项目版本或内容哈希路径），避免每次 POST 当 `<link>`。

`text=` **只出现在这里**（或控制台内部 API），永不挂匿名 `/api/css`。

### 12.4 调用侧怎么选

```
试水 / 文档 / 单款公开包     →  GET /api/css?family&weight&subset
多字体 + 自定义字表 + 域名   →  控制台发布 → GET /p/{slug}/index.css
CI / 脚本按文案切一版       →  POST /v1/subset → 把返回 URL 写入项目或 HTML
谱系缺字补全                 →  family=主|上游 + 同 subset；或项目里绑 fallback
```

### 12.5 边缘与现状（参数谈了也要落地）

1. `cn.windfonts.com/api/css` 须回源 vault（现网 OSS 404）；否则用户复制的链接无效。  
2. 边缘统一认 `subset`（`lang` 可作别名）；`version` 双写可逐步退役，退役须文档 + 前台同步。  
3. 前台生成器：默认 `subset` 按场景（营销 `zh-common` / 阅读 `zh`）；多选字体输出 `|`；补全勾选只加第二个 family。

### 12.6 一句话

**公开 GET 只认 family / weight / subset（+ 兼容 version）；自由字表进 POST；项目把复杂选择烘焙进无参 CSS。**

## 13. 还能提供哪些 API · 给用户什么价值与数据

只谈产品边界，**未排期、未开工**。  
嵌入三轨（§12）解决「怎么用字」；本节解决「怎么发现、选型、合规、运维、集成」。

**完整价值地图 + 现在/近后续/更后分期**见专用稿：  
[`docs/plans/2026-09-24-api-surface-value.md`](2026-09-24-api-surface-value.md)（下文保留摘要，避免双份维护时以专用稿为准）。

### 13.1 现有能力分层（对照）

| 层 | 现网 / 草案 | 用户拿到什么 |
|---|---|---|
| **投递** | `GET /api/css` · 项目 `/p/…` · `POST /v1/subset`（草） | CSS / 子集包，能显示 |
| **目录** | vault `GET /api/fonts` · `:id` · `categories` · `brands` · `…/analysis` | 列表、详情、字符表；计数类字段（浏览 / 下载 / apiCall） |
| **控制台** | HANDOFF 里 `/v1/projects|domains|usage|…` 草案 | 项目、域名、用量、上传、认领、团队 |

缺口不在「再多几个 subset 参数」，而在：**把目录与运营数据做成可集成的机器接口**，让站点、CMS、设计工具、代理商不必爬 HTML。

### 13.2 建议增量 API（按价值，不是按实现顺序）

#### A. 选型与目录（公开或轻鉴权）

| API 意向 | 用户价值 | 可给到的数据 |
|---|---|---|
| **字体详情机读包** `GET …/fonts/{slug}` 稳定字段 | 自建选字器、CMS 插件、内部设计系统 | `family` 短码、中英名、字重列表、分类、厂商、许可摘要、开源绿标、谱系上游、是否可商用网页嵌入 |
| **覆盖 / 字符表** `…/coverage` 或现有 `analysis` 产品化 | 「这段文案缺不缺字」「能不能上标题」 | 码点覆盖率、相对常用字表缺口、预估包体（按 subset）、与上游覆盖差 |
| **许可与证据** `…/license` | 法务 / 采购一次拉齐，少翻详情页 | SPDX / 许可名、链接、署名要求、RFN 限制、网页嵌入是否允许、证明链摘要 |
| **谱系** `…/lineage`（草案已有） | 派生款选型、缺字补全决策 | `upstream`、`group`、同系兄弟、建议 fallback family |
| **搜索** `…/search?q=`（草案已有） | 自然语言 / 场景找字（「海报标题」「正文书写」） | 命中列表 + 简要理由字段（标签 / useCases） |
| **厂商主页机读** `…/foundries/{id}` | 品牌站、认领后 CMS | 简介、站外链接、旗下字体、认领状态 |

价值一句话：**从「逛网站选字」变成「工具链里选字」。**

#### B. 体积与嵌入决策（半公开）

| API 意向 | 用户价值 | 可给到的数据 |
|---|---|---|
| **包体预估** `…/estimate?family&weight&subset` 或 `text` 哈希 | 上线前算带宽 / 首屏预算 | 预估 CSS+分片字节、片数、相对 `full` 的压缩比 |
| **推荐 subset**（输入场景或文案长度） | 非专家少踩 `full` | 建议枚举 + 理由（「短文案 → zh-common」） |
| **多字体组合检查** `family=a\|b` | 谱系补全 / 混搭前自检 | 字重是否对齐、许可是否都允许嵌入、预估双倍体积 |

价值一句话：**少猜体积，少因选错档被流量打爆。**

#### C. 项目与运维（鉴权 · 控制台 API 产品化）

| API 意向 | 用户价值 | 可给到的数据 |
|---|---|---|
| **用量** `GET /v1/usage…`（草案） | 账单、容量规划、异常流量 | 请求数、字节、按字体 / 域名 / 项目、状态码、被拒 Referer |
| **域名与拦截** | 防盗链排障 | 白名单状态、未授权 host 聚合、验证结果 |
| **版本与发布** | CI/CD 推子集、回滚 | 版本号、字节、当前指针、回滚结果 |
| **审计 / 团队** | 代理商、多人协作 | 谁改了项目、密钥轮换时间 |

价值一句话：**字体 CDN 变成可运维的基础设施，而不只是一段 link。**

#### D. 集成与生态（可选，后置）

| API 意向 | 用户价值 | 可给到的数据 |
|---|---|---|
| **Webhook**（发布成功、域名验证、用量阈值） | 接内部监控 / 工单 | 事件类型、项目、时间戳、摘要 |
| **SSO / OAuth 应用令牌** | 第三方主题、建站工具官方接入 | 作用域（只读目录 / 读写项目） |
| **批量 catalog dump**（签名、限频） | 镜像到内网设计库 | 全量或增量 JSON（字段同公开详情） |

价值一句话：**让「文风」出现在别人的产品里，而不只出现在自己的官网。**

### 13.3 刻意不做 / 慎做的「更多 API」

| 想法 | 态度 |
|---|---|
| 匿名 `GET` 带任意 `text=` 即时切字 | **不做**（§0） |
| 把详情页 HTML 当 API | **不做**；给稳定 JSON |
| 暴露原始 TTF/OTF 下载作「开放 API」 | **慎**；许可与带宽；开源可链上游，商业款走授权通道 |
| 实时逐字渲染图 / 截字图 API | **后置**；成本高，和 CDN 主业弱相关 |
| 与嵌入无关的泛 AI 聊天 API | **不做**；搜索选字可做，别做成万能助手 |

### 13.4 对谁值钱（画像 → 数据）

| 用户 | 最想要的 API | 核心数据 |
|---|---|---|
| 前端 / 建站 | css + estimate + 推荐 subset | 短码、字重、subset、字节 |
| 设计系统 / CMS 作者 | fonts + coverage + license | 机读元数据、缺字、合规 |
| 市场 / 品牌 | 项目发布 + 用量 | 稳定 `/p/…`、流量、盗链 |
| 开源作者 / 厂商 | foundry + claim + 旗下列表 | 归属、认领状态、引用量 |
| 代理商 / 多客户 | team + audit + usage by project | 隔离、账单拆分 |

### 13.5 与嵌入参数的关系

- **更多 API ≠ 给 `/api/css` 加更多查询参数。**  
- 投递保持瘦（family / weight / subset）；丰富能力放在 **目录 JSON、覆盖、许可、用量、项目生命周期**。  
- 前台静态站可继续读本地 JSON；对外集成与控制台以 vault `/api/*` + 将来 `/v1/*` 为准，字段对齐后文档化。

### 13.6 分期摘要（细则见专用稿）

| 期 | 做什么 |
|---|---|
| **现在** | CDN `/api/css` 回源；目录 API CORS + 契约文档；详情计数 / 构建期热度；前端档位默认与多 `family` |
| **近后续** | 详情补许可·谱系；analysis→coverage；包体清单 / estimate；推荐 subset |
| **更后** | 项目 CSS、`POST /v1/subset`、用量·域名·团队、Webhook / OAuth |

### 13.7 记录结论（讨论用）

文风**可以、也应该**在「投递」之外提供更多 API，但增量价值主要来自：

1. **可机读的字体事实**（元数据、覆盖、许可、谱系）  
2. **可决策的体积与档位**（预估、推荐）  
3. **可运维的项目与用量**（发布、域名、流量）  
4. **可嵌入生态的集成面**（webhook、应用令牌）——后置  

先把现网目录 API 字段稳定、CDN `/api/css` 回源打通，再按画像抽「覆盖 / 许可 / 用量」做成正式契约，比堆新查询参数更值。
